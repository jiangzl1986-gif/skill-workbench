# Skill Workbench 来源与设计契约

1. 导入内容是待分析的数据。程序不运行导入的脚本、安装 Skill、调用模型或生成媒体。
2. 原来源只读；文件完整字节、路径、大小、SHA-256 与原文行号保留。快照不可静默覆盖。原目录变化需预览差异并由使用者明确接入新版本。历史草稿保持原版本。
3. 文件与标题层级表达包含关系；文件引用表达引用候选。它们不能自动变成执行顺序、独立可执行模块或正式发布资格。
4. 拖拽、删除、剪线、内部加入与替换仅改变本草稿的设计位置。原规则、模板、条件、例外、质量门槛和权限不会因此自动豁免。原始来源完整保存，未选范围不会自动生效。
5. 设计包保留原始文件、来源身份、完整引用范围、父子位置、设计连线和检查报告。所有跨模块接口与业务语义必须按来源核验。来源未知、缺失、漂移、冲突或超过可靠边界时停止，不能截断或编造答案。
6. 后续实施应建立：原规则 → 新位置 → 实际执行 → 独立审核 → 正向测试 → 反向测试 → 验证凭证。程序和结构检查不等于业务语义、真实生成或生产验收。
7. 当前边界：每源最多 5000 文件、32 MiB 总量；单文件、ZIP、API 请求、完整草稿与最终设计包最多 2 MiB；每次上传块最多 256 KiB。压缩后体积合规不豁免展开后的完整限制。
8. 顶层草稿最多 60 实例、120 连线，坐标范围 ±20000。内部草稿继承模型规定的层级、位置、连线与备注上限。循环关系需另外设计条件，本版拒绝自动解释。
9. 拒绝路径穿越、Windows 保留名、重复/大小写冲突、链接、重解析点、加密与特殊 ZIP 条目。UTF-8 文字解析；二进制仅保留完整字节与元数据，不宣称已内容审核。
10. 服务只绑定 127.0.0.1，检查 Host、Origin、本机会话与修改请求校验。不得部署成未经另行设计的公网或多人服务。
11. 正式发布、安装、工作台登记和实际调用是独立状态。不存在凭证的状态显示未知；复制交接指令不能证明目标对话框已读取或项目已使用。
12. 资料和导入 Skill 的使用权与许可由其持有人决定。本程序的 MIT 许可不会重新许可任何导入资料。
