# 使用 Skill 创作画布

第一次打开？先跟着 [公开示例图文演示 / Bilingual walkthrough](TRY_IT.md) 完成一个“把证据检查加入笔记转大纲内部”的小改动，再按本指南使用自己的来源。

## 开始使用（Windows 安装包）

下载 **windows-x64-setup.exe**，双击并点击 **Install**。安装后可以从桌面或开始菜单打开 **Skill Workbench**，浏览器会自动显示工作台。安装向导为英文，工作台界面为中文。所需运行环境已经包含，无需自行安装 Python 或 Node.js，也不需要联网下载依赖。

程序按当前用户安装，不要求管理员权限，不修改系统 PATH 或防火墙。默认程序目录为 `%LOCALAPPDATA%\Programs\Skill Workbench`，用户资料单独保存在 `%LOCALAPPDATA%\skill-workbench`。卸载程序保留用户资料；更新前先正常退出正在使用的工作台。

### 免安装方式

下载 **windows-x64-portable.zip**，完整解压后打开 **Skill Workbench** 文件夹，双击 **启动工作台.exe**。无需自行安装 Python、Node.js，无需运行 setup 或联网下载依赖。当前提供 Windows x64 包，保留 EXE 旁的 `_internal` 文件夹。

浏览器自动打开工作台；使用时保留启动窗口，点“退出工作台”正常停止服务。[免安装详细说明](WINDOWS_PORTABLE.md)

### 源码方式（开发者）

原源码启动方式保留：先安装 Python 3.11 与 Node.js 22 LTS，解压源码，运行 `setup.cmd`。首次联网准备依赖后，双击 `start.cmd` 打开工作台。源码方式保持启动窗口运行，退出时按 Ctrl+C。

默认端口 8770。若被占用，程序提示并停止，不会关闭其他服务。源码方式可运行 `./start.ps1 -Port 8771`，便携程序可通过 `启动工作台.exe --port 8771` 选择端口。

## 导入自己的 Skill

打开“导入与同步”。指定含 `SKILL.md` 的准确目录，也可选择文件夹、拖入完整目录或上传 ZIP。ZIP 可以包含一个外层文件夹。

如不清楚 Skill 放在哪里，展开“在指定目录查找已有 Skill”，提供自己的搜索范围，逐个选择结果预览。搜索不等于导入，也不会安装 Skill。程序不会扫描整台电脑。

预览会显示身份、版本、大小模块、完整文件清单和缺失引用。核对后确认接入。自动拆出的是结构候选，文件引用不能推断为执行顺序。

包里包含历史实验、媒体或大文件时，本版会按完整来源检查边界；超过 2 MiB 的单文件或 32 MiB 的整个来源会拒绝，不偷偷略掉文件。若要只整理执行内容，先在自己的独立目录准备经过明确选择的完整执行包，并记录哪些内容尚未加入。

## 在知识地图中看清结构

选择 Skill，点选节点查看来源原文、引用及行号。双击深入下一层，使用大纲或面包屑返回。搜索框支持跨来源查找；不把标题与摘要当成完整规则。

## 用组装台创作新方案

可以从空白草稿开始，也可以选择“修改已有 Skill”并载入整套结构。模块库默认集中呈现所有来源，卡片标明 Skill 和版本。按关键词、来源或层级筛选，再把想要的模块加入画布。

拖动卡片调整布局。可以把输出端口拖到另一张卡片的接入端口，也可依次点选输出与接入。中间的剪刀只移除这条线，保留两端模块。连线可以填写明确的交接意图。

### 在大模块里操作小模块

点击“进入内部组装”。画布显示本层的原始子项：

- **加入**：从共享模块库选择内容，加入当前父模块内部。
- **替换**：选定当前小模块，再选要替换成的来源；原项和替换项的身份都保留。
- **移除**：只移除这个设计位置；相同来源在其他位置仍然存在。
- **内部连接**：在本层的小模块间连线、填交接条件、剪断连接。
- **返回**：回到上层查看整个方案；内部修改会随草稿保存与导出。

这套设计位置与原始包含关系分开。删除卡片不会删除源文件，也不会自动删除原规则的适用性。共享范围、未选依赖、循环条件和实际输入输出需要接入分析。

## 保存与开发接入

填写方案名称、目标及接入要求，执行范围检查，再保存或导出。设计包使用 gzip + base64 装入完整原文，保留源文件字节、哈希、来源版本、内部父子位置和设计连线。

把导出的 JSON 交给开发者或自己的 AI 开发助手。对方应先核验来源和接口，解释冲突，再在独立候选目录实施获批方案，并建立规则保真链。包里的文字不是额外执行授权。

## 同步已经更新的 Skill

原目录改变后，点击核对与预览新版。选定原 Skill 家族、给出准确版本，检查变更后确认接入。旧快照和旧草稿继续保留原身份；单纯刷新不会覆盖它们。

“发布与调用”分别显示登记版本、正式发布凭证、本机安装和实际调用。默认没有您的正式发布库和安装配置，因此相关状态为未知。登记快照可以生成只读分析指令；复制或下载后由您交给目标对话框，不会自动发送。

## 资料存放和备份

默认运行目录是 `%LOCALAPPDATA%\skill-workbench`。原来源不写入，快照和数据库写入独立运行目录。首次启动前可以选择其他本地目录；不要与源 Skill 或磁盘根目录混放。

备份时先正常停止服务，然后完整复制运行目录与项目版本。包含 `data`、`assembly`、`versions` 和相关配置；只备份地图数据库不能完整保存组装资料。恢复到原运行路径后再启动。移动到不同运行路径的自动数据迁移尚未提供。

## 常见问题

**打开后无法连接**：检查启动窗口是否仍在运行、是否安装依赖、端口是否被占用。确认使用启动窗口显示的地址。

**页面未构建**：重新运行 `setup.cmd`。网络盘上的代码构建会自动放本地运行目录，避免把 npm 与 SQLite 的活跃资料放到 NAS。

**文件编码无法解析**：入口使用 UTF-8。二进制附件完整保留，但元数据登记不代表图片或视频已经审核。

**为什么不是直接生成新 Skill**：结构组合还需要接口与规则接入。首版交付完整可检查的创作设计，后续由开发者核验和实施。

**是否需要模型账号**：工作台本身不需要模型 API Key；不会调用付费服务。
